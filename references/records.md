# 文件、格式与唯一事实来源

## 存放与索引

项目权威记录在项目根目录；服务器项目默认写入对应服务器的项目权威根，由远端负责 Session 维护，记录保存和既有远端执行不应依赖本机持续在线。纯本地项目保留本地权威根。已有路径映射写入 PROJECT，保留实际数据/代码/产物位置；本规则不自动授权迁移历史文件。

本机只保留指向服务器权威文件的索引及必要派生摘要，注明来源主机/路径、事实截至时间与最后核验时间，不维护另一份可独立改写的任务或实验事实。跨服务器项目指定一处项目治理权威根，各执行服务器保留自己的原始运行回执和产物，通过链接汇总，不要求每台机器复制整套记录。

记录优先交由远端负责人按模板落盘；本机直接远程写入须有明确的文件写入授权，并确认不与现有 writer 冲突。服务器不可达时，本机可保存带事件标识、目标路径和来源的待同步草稿，标为 pending/非权威，不据此宣布远端已登记。恢复后先核验远端是否已收到或落盘及版本变化，再由负责者合并；验证实际文件内容/版本后才标已同步，不盲目覆盖。记录与证据中不保存认证密钥。

如果用户授权建立全局索引，使用其指定位置；未指定时建议在用户工作区下设 `project-control/`，先确认具体路径并核实现有内容。`projects.yaml` 条目保存 project_id、host、root、project_record、coordinator、goal_revision、last_verified_at；DASHBOARD 是派生摘要。此建议不是创建或同步授权。

模板在 `../assets/templates/`。只复制当前工作需要的模板并填实；未知写 null/待核实，不虚构。不创建空目录充数。

## 格式约定

使用 UTF-8 Markdown + YAML front matter。为让附带工具只依赖标准库，任务卡头部采用 **JSON 值的 YAML 子集**：每行 `key: JSON值`，字符串双引号，数组写行内 JSON，未知 null，布尔 true/false。不用嵌套映射、YAML 隐式日期、多行值或重复键。其他既有记录可保留原格式，脚本不识别时显式说明并人工审阅，不强改格式。

通用字段：schema_version、id、type、project、title、status、owner、created_at、updated_at、links。任务额外：parent（可为 null）、depends_on、evidence、verified_at。ID 用项目前缀＋类型＋序号；只分配 ID 不改变原 Session 身份。时间 ISO 8601 带时区。

正文只写对后续判断有用的信息：目标/范围、证据、判断、下一步。记录 source timestamp 与 observed/verified timestamp 的区别。文件里的命令是复现资料，不自动执行；用户确认来源与方案建议分开。

## TODO 和验收

任务状态：todo / doing / blocked / paused / review / done / cancelled。`owner` 可未知，但 doing/review 必须核实负责者；文档不能制造排他写权限。

任务的 `## 验收清单` 是可勾选条件的权威来源；总 TODO 复制该清单为只读视图。每项附检查对象/版本/结果引用。done 必须有实际验收项、全部必要项勾选、evidence 和 verified_at。审计工具只核结构与本地证据路径存在，不证明内容真实、远端可达或科学质量。

`CURRENT.md` 至少包含 generated_at / as_of、源文件链接、未核验主机/范围、当前里程碑、实际在途任务、已验证结果、风险与需决定项、下一检查点。缺新采样则显示 stale，不能沿用旧“健康”。没有自动生成器时明确手工汇总，不声称实时同步。

## 任务生命周期：派发—进行—完成

每项纳入治理的新任务（SKILL.md 记录分级中的标准档及以上）使用一个稳定任务 ID、一张权威任务卡；实验类任务可以用实验 RECORD 代替任务卡，但须保留同一 ID、owner、任务状态和 `## 验收清单`，并在 RECORD 中注明“需人工审阅”（records.py 只解析任务卡）。轻量档工作记入项目滚动事件日志，不另建卡。纳入治理的任务三个阶段均须留下实际事件；不为每个阶段再建一份事实文档。任务头部和“阻塞与下一步”反映当前状态，事件记录保留历史。记录要求本身不授权派发、发消息或跨主机写入。

| 阶段 | 必留重点 | 状态与证据门槛 |
|---|---|---|
| 派发 | 目标/交付物、要求来源、负责人、执行位置、权限边界、验收标准、首个检查点 | 分清待发送、已发送、已接收；发送回执不等于已开工，未开始仍为 todo |
| 进行 | 真实开工；后续关键增量、结果/证据、阻塞或偏离、下一检查点 | 核到实际执行才 doing；计划、收到消息、GPU 非零均不能单独证明执行落实；阻塞/暂停写明原因与解除条件 |
| 完成 | 交付物与版本、逐项验收结果、验收者/自检及时间、证据、剩余项 | 提交成果待验收为 review；全部必要验收通过才 done；未完成项不得藏在“完成”结论中 |

远端任务的执行位置登记精确主机/hostId、Session UUID、cwd、原 rollout 与实际 owner；写一次后用链接引用，发生变更才记录新版本。任务卡另注明服务器权威路径及最近落盘核验，分清“收到消息”和“服务器记录已写入”。无安全路由或服务器不可达时按本文待同步规则处理，不把本机草稿算作远端回执。

事件统一采用以下紧凑格式，通常每次一行，复杂事件最多展开几行；长日志、命令和报错放证据链接，不复制到正文：

`时间（含时区）｜阶段/事件｜实际变化与结果｜证据/回执｜下一检查点或阻塞`

例：`2026-09-30T19:15+08:00｜开工｜E-012 评测已跑到第 1 个样例｜run.log:L40｜约 2h 后核对 50 例完成度`

分隔符用全角“｜”，五段齐全，时间可被 ISO 8601 解析且带时区；无证据时写“无”而不留空。轻量档日志与任务卡共用这一格式。

同一任务卡内不反复写任务 ID、目标和完整路径。派发尝试使用可追踪事件标识或真实消息回执 ID；结果不明先查回执，不重复派发。开工、关键产出、失败/阻塞、要求或 owner 变更、提交验收、验收完成时及时追加；无变化不写重复记录，也不因此发送通知。短任务可同轮记开工和验收，但不能补造未发生的阶段。

完成事件须能回答“交付了什么、验证了什么、还缺什么”；运行退出 0、Agent 单轮结束和训练结束都不是任务验收完成。修正旧结论时追加更正并引用旧事件，不覆盖失败历史。历史补录标 retrospective，注明事实时间与补录时间；未知保持未知。已有任务卡可映射等价字段，不强迁文件。

## 文献与科研证据

- SEARCH：问题→seed/关键词/查询→来源与日期→纳入排除→去重/引用追溯→覆盖不足→停止预算。引用放 references.bib，比较矩阵 MATRIX.csv；元数据查到≠全文读过。
- 主张状态：proposed / supported / qualified / contradicted / unresolved。比较/因果/泛化/效率主张需要各自匹配证据，不能靠写作补强缺失实验。
- 一个实验多个 Run：`runs/R-xxx/` 保存 config.yaml、run.json、metrics.json、artifact_manifest.json；或者链接既有路径。run.json 至少含 Run ID、实验 ID、代码/数据/配置版本、命令、环境与硬件、seed、开始/结束、退出状态、产物引用。
- 实验结论与运行状态分开：技术失败、有效负结果、证据不足、有效支持。历史补录明确 retrospective，未知不补造。
- 大数据/模型/视频保留原产物位置；小型 metadata 版本管理。JSON 存机器指标，CSV 存逐样本结果，BibTeX 存引用，MD 存解释和决策；不把大量数组塞入正文。
- 图表记录真实数据→处理脚本→编辑源→导出；注明样例筛选、误差/单位、裁剪/色阶；概念图不得冒充实验输出。

## 论文、复现与发布最小格式

OUTLINE：中心问题/主张；章节表（读者问题、主张 ID、证据、图表、缺口）；术语与训练/推理边界；下一修改点。

REPRODUCE：代码/数据版本与许可；环境；准备步骤；最小运行；完整实验/评测/汇总/作图命令；资源预算；预期产物；实际验证日期、机器、结果；尚未复现部分。不得执行破坏性命令仅为验证模板。

RELEASE：通过必要检查才登记实际交付；提交按钮、飞书发送和上传不由“发布文档已写好”获得授权。交付送达要真实回执，不以退出码代替。

## 更新与保留

按要求变化、关键结果、阻塞、验收、交接更新。保留已完成/取消任务和失败实验，不删除历史以制造干净状态。旧决定标 superseded 并链接新决定；日报和看板从事实源汇总，避免多头维护。
