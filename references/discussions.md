# 并行讨论与会商

用户可同时问多个相关 Agent；并行思考本身不需要总控审批。实际创建/委派 Agent、读取外部会话、发送跨任务消息，仍要当前授权，本参考不赋予这些能力。

重要议题使用 `management/discussions/Q-xxx/`：

- QUESTION.md：问题、共同事实与来源、目标版本、限制、需要什么输出、讨论预算/结束条件；注明现有执行是否继续。
- opinion-身份.md：每人独立文件，用 opinion 模板。首轮需要独立判断时，不先提供其他 Agent 的结论。
- SYNTHESIS.md：指定汇总者整合共识、差异、依据、成本、待验证问题与建议。

普通短讨论直接在相关任务记关键结论，无需目录。需要落盘才读取记录规范。

## 规则

1. 各写自己的意见；共同问题版本改变时记录变化，提醒旧意见可能基于旧前提。
2. 分清事实、引述、假设、建议、用户确认决定。保留来源与不确定性。
3. 不按多数票认定科学事实；有证据的少数意见保留。无法判断时设计区分方案的低成本实验。
4. 汇总者协调，不垄断解释权；用户可直接采纳任何方案。
5. 讨论本身不暂停原任务、不启动实验、不改变共享目标；实际冲突或无效证据则明确指出影响范围。
6. 第一轮独立意见→一次汇总；需要时补有针对性的质疑。按用户时间/成本预算结束，不强制无限辩论或始终固定人数。
7. 被接受的决定写 D-xxx，执行写 T-xxx/E-xxx。两个方案并行验证时隔离数据/配置/输出和资源，禁止覆盖彼此产物。

## 汇总正文

```markdown
# 议题汇总
## 共同事实与版本
## 有证据的共识
## 分歧
方案、关键假设、支持/反对证据、成本、适用条件。
## 最小验证或建议选择
## 已确认决定
确认来源；未确认则留空或标待决定，不能把推荐写成已批准。
## 后续任务与未解决项
```
