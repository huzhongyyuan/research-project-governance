# 过程、算力与远端执行安全

治理原则要落到操作上。本文件是远端训练、评测、渲染等长任务的通用操作规则，每条附正例和反例。它不授权任何生产操作；停止、启动、占用资源仍按当前授权。

## 1. 停进程：只按精确身份

- 启动时就把根 PID 写入任务记录或 pid 文件；停的时候以这个已登记、已核实的根 PID 为准，沿父子关系展开到子进程。完整启动参数、工作目录、启动者只用于核对（确认 PID 没有被复用），不作为选择依据，因为相同的相对命令可能属于别的会话。
- 只停自己启动的或用户明确点名的进程；写成脚本执行，先打印目标，停后核对结果。
- 正例：从 pid 文件读到根 PID 12345，核对其参数仍是 `./run_eval.sh`、工作目录是本任务目录，再对它和它的子进程发送终止信号。
- 反例：`pkill -f 任务名`、`pgrep -f 任务名 | xargs kill`。模式会匹配到发起它的远程 shell 本身，或其他会话里的同名任务。
- 其他会话、其他用户、资源占位进程即使占着资源也不停；需要资源时报告占用者并请求决定。

## 2. 启动与后台任务

- 远端长任务脱离当前会话运行，并把输出重定向到文件，否则远程 shell 可能一直等到任务结束：`setsid nohup ./job.sh > run.log 2>&1 < /dev/null & echo $! > job.pid`。一次性远程命令不读取本地输入（如 `ssh -n`）。
- 启动后立即核验三件事：进程存在、日志在增长、首个检查点出现（第一个训练步、第一个样例）。"命令已发送"不算已开工。
- 含引号、多行或非 ASCII 的命令与提示词，先写成文件再传到远端执行；执行前做语法检查（`bash -n`、解析器检查）。
- 反例：把长提示词直接拼进远程命令字符串，或用文本替换改脚本，导致脚本一启动就语法错误退出，而等待方毫不知情。
- 后台等待器盯住精确对象（PID，或状态文件里的明确完成标记），同时处理"对象已消失"。不要用会同时匹配新旧任务的模式等待。

## 3. 非交互环境

- 后台和非交互远程执行时，HOME、PATH、语言环境、凭据目录可能与交互终端不同。依赖凭据或配置目录的工具要显式指定目录，正式使用前先跑一次最小调用确认可用。
- 正例：先让工具执行一条只返回固定字符串的调用并成功，再启动正式的循环任务。
- 反例：循环任务连续鉴权失败，被误判为"工具损坏、需要重新登录"；实际只是后台环境读错了配置目录。

## 4. 共享算力

- 使用前确认占用者：显存或内存、进程、启动者，是否为占位或保活进程，是否属于其他会话。空闲与否以进程归属为准，不看利用率。
- 登记本任务占用的资源、预计时长和释放条件；结束或切换时释放，并写进交接记录。
- 能并行的阶段（分片预处理、不同测试集的打分）按可用资源并行；只有真实依赖或独占资源才串行。

## 5. 进度与预计时间

- 预计时间要写依据：已完成量、同一阶段的实测速度、剩余量、后续阶段。格式为"约 N（依据：X/小时，剩 Y）"。
- 不用别的阶段、别的机器的速度外推；阶段切换后重新实测。
- 训练损失进入平台期，既不说明模型没进步，也不说明在进步；判断继续训练是否有价值，要用固定随机种子的验证评测。

## 6. 完成判定

- 输出文件数量达标不等于完成：逐例核验状态、错误字段和基本形状（长度、尺寸等），失败例单列。
- 进程退出码 0 不等于成功：有些脚本单例失败仍返回 0，要逐例检查结果记录。
