# 精简汇报、实验汇报与科研周报

内部多核查一步，对外少说几句。汇报是带截至时间的派生视图，不改变任务卡、实验回执或主张卡的权威地位。

## 汇报前自查，不逐题输出

- 做完了吗：区分已交付、已验证、仅运行结束、尚缺验收。
- 比上次推进了什么：核对同一范围、版本和口径，链接实际改动、结果或产物；找不到上次基线就说明。
- 对研究有什么帮助：支持、限定或反驳哪个主张；还缺哪个对照或证据。非论文任务不强行编造论文价值。
- 有没有偏离、重复或冲突：对照最新明确要求和实际执行者；无法核实写未知。
- 下一步是什么：授权内最有价值的动作、阻塞解除条件和下一检查点。需要用户决定时给推荐方案及代价，不把建议写成批准。
- 还要多久：有稳定速度、剩余量和依赖依据才给区间及条件；否则写缺少什么，不承诺虚构 ETA。

默认回复“一句结论＋1–3项重要变化＋下一步”，详细证据链接展开。已经告知且未变的背景不重复；用户要审计全文时再展开。没有新成果也如实说明，不为凑报告进行无授权实验。

## 双入口汇报

外出助手与办公室本机使用相同采样事实，不各写一套进度。外出默认给手机可读摘要：一句结论、需要用户决定的动作、重要增量/阻塞、下一检查点及证据入口；避免长表格、路径和 UUID 堆叠。身份细节保留在审计记录，需要时展开；用户要求全文时仍可提供。

回到办公室优先报告上次已核验检查点以来的变化，提供代码/产物/实验证据以便深入审查。不重复已经确认的决定，不把历史成果算作新进展。找不到上次基线时明确说明，不能编造“离开期间”的变化。

两端均标明事实截至时间、未核验范围及待交接状态。完整记录未落盘或接收方未确认时，不写“已同步到总控/另一端”；发送成功需实际回执。简报准备完成不等于已发送，本规范不新增外发权限或通知频率。

## 实验汇报

按记录分级读取权威来源：轻量档读滚动事件日志及其链接的原始日志/指标，标准档以上读任务卡或等价 RECORD 与 Run，正式评测再读协议；只看训练结束或 Agent final 不足以验收。记录不全就在对应项写“待补”，不补造配置或数值。

详细事实按记录分级保存：轻量档的短实验记在滚动事件日志，标准档以上用 `management/experiments/E-xxx/RECORD.md`（[实验模板](../assets/templates/experiment.md)）。对外每个实验写成六项（与周报相同）：

1. **实验背景**：为什么做，要回答什么问题，1–2 句。
2. **实验设置**：改变的变量、固定不变的条件、数据、checkpoint、seed、机器与输出路径。
3. **实验分析（可选）**：关键指标与基线对比、现象、原因假设；假设标“待验证”，不写成根因。
4. **多媒体 demo**：视频、音频、文本样例的链接，注明对应哪组设置；没有就写“无”。
5. **实验结论**：一句话，属于有效支持、有效负结果、证据不足或技术失败之一；只跑一次或缺对照要写明。
6. **TODO**：待解决的问题和卡点，附下一个检查点。

设置、指标、demo、TODO 用表格，背景、现象、原因假设和结论写成文字，规则见下文“表格还是文字”。

不同划分、数据量或评测协议的结果不能直接拼比较。失败与反例写进结论，不挑最好的 seed 或样例；运行结束、技术有效、科学结论成立分开说。

## 项目常问问题与提前准备

在已授权的项目执行与记录维护中使用本机制；只读咨询只给归纳建议，不顺手写项目文件。它由 Agent 在现有工作节点执行，不会独立唤醒、遍历全部私人会话或新建定时任务。

### 识别与登记

- 从当前项目已提供或获准读取的对话、用户修正与既有交接中识别语义相同的追问。跨独立提问事件重复出现，或用户明确说“以后都关注/每次都检查”，才登记为 active；单次问题或模型预判标 candidate，不冒充用户长期偏好。
- 同一消息的复制、摘要转述和重复读取不算新提问。保留可定位的原消息来源、日期与适用范围；无法读取历史就说明覆盖不足，不伪造频次。
- 采用 [问题清单模板](../assets/templates/questions.md)，映射到既有类似文档也可以。服务器项目由负责 Session 维护服务器权威根下的 `management/QUESTIONS.md`；本机只索引。按 records.md 的 owner、写入与待同步规则处理，不产生第二 writer。
- 问题清单只管理关注点、证据入口和带时间的答案摘要；真实任务、运行和科学结论仍以各自权威记录为准。项目问题不自动升级为全局偏好。用户改变关注范围时更新或标 retired，保留替代关系。

### 什么时候提前做什么

接续项目时读 active 项；关键实验结果/验收/阻塞变化时，以及每次汇报前，检查与当前阶段相关的问题。优先准备影响用户判断且可低成本核实的答案，不每次重读全部历史。

每项确定证据来源、刷新条件和最近核验时间。例如“是否完成”看验收与回执；“比基线好多少”看同协议指标和波动；“为什么失败”区分日志观察与尚未验证的根因；“还多久”核实剩余量、速度和依赖；“能否用于论文”看主张及缺失对照。这些是通用检查示例，不代表用户已经问过。

读取已有结果、核对版本与计算已有可比指标的差值可在原授权内提前完成；输出保存仍遵循文件权限。新训练、评测、渲染、付费调用、外发或变更生产任务不因预判问题而自动获准。缺证据时准备缺口、最小验证建议及成本，不启动额外实验来凑答案。

### 答案与对外汇报

答案状态为 ready / stale / missing / needs_permission，注明 as_of、verified_at、证据版本和入口；版本、协议、目标变化或超过该问题的刷新条件后，旧答案转 stale。无法重新核验就明确未知，不沿用旧“正常/完成”。没有完整答案时，准备好缺口与决定项也有价值。

默认仍按原简报结构输出，只主动呈现重要新答案、失败、阻塞或需决策项，其余通过链接供展开；不把全部 FAQ 附在每次回复后，也不因清单更新增加通知。区分“机制已写入 skill”“项目清单已落盘”“本轮答案已有证据”，不混称自动准备完成。

## 学生科研周报

周报是给导师和同组对齐信息用的：有进展就写，无进展不写，简洁高效。

**更新节奏**：每天有进展随手记一条；至少周二、周五晚上各更新一次。当天没有进展不写空条目，也不用计划、读书笔记或运行次数凑数。

**结构**（[周报模板](../assets/templates/weekly-report.md)，[填好的示例](../assets/examples/weekly-report-example.md)）：

| 部分 | 写法 |
|---|---|
| 顶部 | 更新日期；本周一句话（推进到哪一步、最大卡点） |
| 本周实验总览 | 表格，每个实验一行：日期、实验、变量、关键结果、结论、状态 |
| 实验进展 | 按日期倒序，一个实验一条，每条用“实验汇报”的六项；跨周运行只写本期新增 |
| 卡点与需要帮助 | 表格：卡点、已尝试、推荐方案、需要谁决定；没有就删掉 |
| 下一步 | 表格，最多 3 项：产物、负责人、验收条件、预计时间；计划不等于已获批准 |
| 随手记 | 表格，每天有进展追加一行；周二、周五把有结论的条目整理进实验进展 |
| 资料与笔记 | 表格：日期、主题、链接；原理学习、论文阅读等不进实验进展正文 |

**表格还是文字**：

| 用表格 | 写成文字 |
|---|---|
| 实验总览、各组设置、指标对比、demo 列表、TODO、卡点、下一步、随手记、资料链接、数据集清单、Run 索引 | 实验背景、现象描述、原因假设、带限定条件的结论、原理说明 |

表格规则：每表不超过 6 列，不合并单元格，单元格不放长句（约 20 字以内，放不下就挪到表下文字）；指标表头标 ↑/↓，带单位，每列最优值加粗；结论和状态用固定词（结论：有效支持 / 负结果 / 证据不足 / 技术失败；状态：计划中 / 进行中 / 已完成 / 已停止），方便扫读。

**整理杂乱周报时**：按日期抽出每个实验，归入六项；同一实验的多次记录合并成一条，保留日期；学习笔记移到“资料与笔记”；原文缺的项写“待补”，不编造。数字照原文转录并附来源；没有重新核验的只在该条末尾标“（转录，未复核）”，不在全文堆免责说明。发现前后矛盾（如同一 run 的口径不一致）写进该条 TODO。

**贴到飞书**：不要直接粘贴 Markdown 原文，飞书会把表格显示成竖线文本。先转成富文本再粘贴：

```bash
python3 /path/to/research-project-governance/scripts/feishu_paste.py 周报.md   # macOS：复制为富文本，到飞书 Cmd+V
python3 /path/to/research-project-governance/scripts/feishu_paste.py 周报.md --output 周报.html   # 其他系统：浏览器打开后全选复制
```

表格、标题、加粗、列表会变成飞书原生格式。周报正文不写 HTML 注释和模板提示语；路径用 `code` 包起来即可。新建整篇文档也可以用飞书的“导入 → Markdown”。

获准保存时写项目内 `management/reports/weekly/YYYY-Www.md`；同周修订直接在原文更新并保留日期。写好不等于已发送，不自动创建周报定时器或发给导师。

## 给其他同学使用

可分享 skill 文件夹和空模板；不附带私人项目、会话、实验数据、凭据或服务器权限。由同学指定自己的项目根和资料范围。专业论文技能不可用时遵循主 skill 的降级说明，不声称已完成专业审稿。已有记录不足时先产出有明确缺口的周报草稿，不逼迫补造完整台账。
