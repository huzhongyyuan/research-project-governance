# 新项目启动

用户讲目标，Agent 把现有资料整理成可执行的第一阶段；不要求用户先填满模板。

## 判断启动权限

“新项目怎么办”是咨询，给启动方案，不自动落盘或调度。明确要求在指定项目初始化时，才在该范围建档并推进已授权工作。目标路径未给且不能唯一确定时，先确认根目录；不要把 skill 安装目录或任意旧项目当新项目根。

只追问会改变研究方向、验收、成本或权限的缺失信息。非关键未知标待核实，合理假设明示；“目标高水平论文”不等于创新成立，也不自动授权大规模训练。

## 从目标到首个检查点

1. 检查指定范围已有 AGENTS、代码、数据、讨论与在途任务，复用记录；已开始且杂乱时转存量接入，不另起平行项目。
2. 明确问题、目标用户/场景、现有方法的已知缺口和证据来源。未经核查的不足只作为假设；真实研究设计和文献判断沿用主 skill 的科研接口。
3. 给第一阶段设可检验的问题：最小验证能支持或排除什么，交付物是什么，资源上限、停止条件和接受门槛是什么。
4. 近期任务拆到产物与验收，远期只保留里程碑。负责人未知可留空；不能仅登记姓名就声称对方已接收，也不能自动创建角色 Agent。
5. 在已确认的目录和权限内开始首项工作；目标改变、额外算力、外部发布或共享 writer 冲突再请求决定，不逐步重复审批。

## 最小记录

按 SKILL.md 的记录分级起步，默认只建两份：

- `management/PROJECT.md`（`project.md` 模板）：当前目标与来源、范围、首阶段验收、预算、权威路径映射。
- 滚动事件日志：沿用已有 HANDOFF 等交接文件，没有时建 `management/LOG.md`，按文件与格式中的事件格式逐行追加。

某项工作达到标准档（约 1 GPU·天以上、跨 owner、不可逆、影响资源分配）时，才为它建 `management/tasks/T-xxx.md`（`task.md` 模板），`TODO.md` 从任务卡派生；进入论文的结论再加主张卡。`CURRENT.md` 只在需要给他人看快照时手工汇总。已有 `AGENTS.md` 只在获准时合并必要规则，不覆盖；文献、实验、讨论记录发生时再建，不预铺空目录。

已有且获准维护的全局索引只增加项目入口，不复制项目内容。没有全局索引不妨碍项目推进，也不据此自动创建或同步。

新参与者先读目标、当前状态及其任务卡，核对责任和共享写入边界。用户仍可直接与任何相关 Agent 讨论；讨论中产生的执行要求按来源和权限分别处理。

启动汇报：当前已建立什么、第一阶段要验证什么、立即执行的首项及验收点；只有关键缺口才提问。启动建档完成不等于研究完成。
