# 项目 Agent 办事规则

本文件是待适配模板，不能覆盖现有 AGENTS.md；只在用户授权范围合并相关条款。

## 开工入口
读取项目目标与路径映射、按记录分级读取滚动事件日志或当前任务卡，以及适用的协议；不要求每次加载全部历史。

## 协作
- 用户可以直接与任何相关 Agent 交流。接收者记录明确要求、来源和影响；想法不是执行许可。
- 按任务/文件/运行明确责任，独立任务可并行。写共享产物前核实实际 writer；不明则先只读，不抢占。
- 改动在原许可和目录边界内进行；新增预算、外部动作或冲突需确认。
- 盘点、讨论和审查不自动授权启动/停止/恢复生产任务或发送业务消息。
- 服务器项目优先由本机协调、监控对应服务器的既有 Session，远端负责人执行并维护服务器上的权威记录；本机只保留索引和带采样时间的摘要。精确核验 owner 后走已授权渠道，不启动竞争执行者；不可达时标待同步，不声称指令已接收或记录已落盘。

## 记录与验证
- 任务卡为 TODO 事实源；每完成一项验证一项。done 要有验收证据，取消与暂停不能算完成。
- 实验 Run、评测结果、科学主张分开；保留失败、负结果和缺口。
- 只在关键事件更新；总览和汇报引用来源及采样时间，不重复维护事实。
- 遵循本机/项目已有论文技能与审稿要求，不用格式完整替代科学验收。

## 汇报

- 先核查验收、实际增量、研究价值、偏离/冲突、阻塞与下一检查点，再给结论、最多3项重要变化和下一步；证据通过链接展开，不堆工具流水账。
- 有依据才估计时间；实验结束不等于质量通过或主张成立。周报对照上期承诺，保留未完成项和有效负结果，不另建一套事实台账。
- 在获准维护项目记录时，把有来源的反复追问或明确长期关注项登记到服务器项目的 QUESTIONS.md（纯本地项目留本地）。关键结果出现与汇报前核查相关证据，提前准备简短答案；未知或过期明确标记，不新增实验、权限、后台任务或重复通知。

## 项目特定约束
填写实际允许/禁止的目录、数据隔离、资源预算、发布规则；不复制其他项目旧事故为全局禁令。
